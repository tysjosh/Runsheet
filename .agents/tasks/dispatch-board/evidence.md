#### Decisions and notes

- Gate 0 records no `GateOutcome`, so `GateEvaluation.outcomes` and `GATE_ORDER` stay exactly as they are for every existing caller; it either raises or returns.
- A `bp-` run whose plan doc is missing, foreign-tenant, or not `source: dispatch_board` passes gate 0 (design K8.6 gates only board plans). Only a missing reader or a read error fails closed.
- `dispatch_board_drafts` map-shaped fields other than `applied_commands` (`lanes`, `order_index`, `acknowledged`, `dismissed_suggestions`, `publishes`) are `object` + `dynamic: true`, i.e. still searchable; the design names only `applied_commands` as non-indexed. Command-log `lanes` is a plain `object` so `term lanes.truck_id` works for history (R22.3).
- `relink_dispatched_assignment` also mirrors to the relational row (`mirror_current_state_upsert`), because no guarded upsert follows a relink the way one follows `claim_assignment`.
- Risk for the reviewer (design-literal, not changed): the driver endpoint's guarded write compares against `es_documents`, but its base read is `FuelOrderRepository.get`, which serves the relational projection when `COMMERCE_READ_FROM_POSTGRES` is on. Every order write path mirrors after commit, so they agree in practice; if a best-effort mirror write failed, that order's driver transitions would 409 (and be retried) until the next mirrored write. Reading the base doc with `get_current` would remove this, but it changes the read path the design specifies, so it's left for review.
- Pre-existing, not caused here: `tests/unit/test_bootstrap_driver_wiring.py::TestOrderServiceWiring::{test_exactly_one_invoice_subscriber_on_order_delivered,test_invoice_subscriber_uses_the_container_invoice_service}` fail when that file is run alone, on the base commit too (checked with `git stash`); they pass in the full suite.
- Disk: free space was 7.1 GB at start and fell to 3.3 GB during the spike. Cleared npm and Homebrew caches; after the spike deleted the worktree's `runsheet/node_modules`, `runsheet/.next`, the spike's test output and the Playwright browser cache (all regenerable) → 5.5 GB free. No Docker build was run. Phase 4 needs `npm ci` and `npx playwright install` again in the worktree, and more free disk before `npm run build` or any Docker build.

#### Decisions and reasons

- **Post-publish rules are lane checks, not command checks.** `stop_pinned` / `load_started` are computed in `validate_lane` by comparing the lane with `publish.published_content`, the orders' statuses/`assigned_run_id` and the executions' `completed_stops`. A command that breaks one produces a lane with a block and is refused at K4.2 step 9; a lane left that way by a rollback shows the block until fixed. This gives freeze rule 11 (e) without a special path: a pinned order on any load other than the one its `assigned_run_id` names blocks with "Started on {truck}. Move it back." and a `move_back` fix link (`FixLink` gains `move_back` and `terminal` kinds plus `truck_id`/`load_id`), and the move back clears it.
- `validate_lane(ctx, lane, *, draft=None, focus=None)`: the extra `draft` keyword is needed for the cross-lane parts (double booking, which runs belong to the draft).
- **Router registration.** `bootstrap/routing.py` is only the idempotent mount helper; the router is included in `main.py`'s import-time list (the endpoint registry introspects import-time routes) and mounted again through `mount_router` in `bootstrap/agents.py`, like the MVP routers.
- **Publish, publish status and suggestion reject routes exist now** with full body parsing (so task 13's body tests run); until Phase 2/3 configure their services they answer 503 `reason: service_not_configured` (status: 404).
- **Draft creation.** The Postgres test found that two first commands racing an `atomic_update(upsert=…)` insert raise `IntegrityError`. The first command of a day now creates the empty draft with `create_document` (insert-if-absent), then runs the CAS on the stored row.
- **History filter** uses a flat `truck_ids` keyword on the command log: the Postgres translator's `term` matches inside a keyword array but not a path into an array of objects (`lanes[].truck_id`).
- `TenantContext` has no `settings` attribute (the guard builds it from settings but doesn't keep them), so the zone is `get_tenant_timezone(tenant_id, getattr(ctx, "settings", None))` → `America/Chicago` today; the draft keeps the zone it was created with (E11).
- Qualification is read once per driver per context with route requirements built from all of the context's orders (conservative; every catalog fuel is hazmat + tanker, class A).
- If the orders source is unreadable during a command the service answers 503 rather than letting the engine report `unknown_order`.
- Engine narrowing (each a 422 with a reason): `discard_lane_changes` refuses with `order_on_other_lane` / `discard_moves_dispatched` instead of moving other lanes' orders; `remove_lane` also refuses a never-published lane that holds an order dispatched on another lane (`lane_holds_dispatched_orders`); unassigning a dispatched order puts it on the shelf (R13.5) and unassigning a shelved one is refused. An explicit `target.index` counts positions after the moved stops are taken out.
- Contract lift: active `supplier_contracts` whose `preferred_terminal_ids` contain the load's terminal; warn when `percent_of_minimum` ≥ 90.
- Not produced in Phase 1: `terminal_supply better_terminal` (needs the sourcing recommender; no design-stated trigger) and the `suggestion` rows (K9, Phase 3). The driver tray carries CDL/hazmat/status and pairing; eligibility reasons are filled only for drivers on lanes (one qualification call per tenant driver per snapshot would be up to 500 calls). Flagged for task 26 (DriverTray).
- Broadcasts go through an optional `ws_manager.broadcast_board_event(...)`; nothing is sent until Phase 3 provides the manager.
- Test-environment note: `tests/postgres/conftest.py` deletes every `pytest_docstore_%` row at teardown, so a Postgres test run from another checkout on the same local database wipes rows mid-test. Two early runs of the new Postgres test failed that way while another agent's pytest was running; isolated reruns pass.
