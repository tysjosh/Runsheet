# Implementation plan: Dispatch Board

Source of truth: `design.md` revision 4 and `requirements.md` revision 4 (R1–R25, N1–N7, Q1–Q16). Work on the current feature branch (`production-readiness/go-live-blockers` or its successor) per the standing permissions; deploy only from a worktree pinned to a reviewed commit with green CI. Every task leaves backend and frontend green.

Commands:

- Backend (cwd `Runsheet-backend`, `PY=venv/bin/python`): targeted `$PY -m pytest --no-cov -q -p no:cacheprovider -o log_cli=false <paths>`; Postgres suite as in `loading-plan-executor/plan.md`; endpoint registry `$PY scripts/generate_endpoint_registry.py` then `git diff --exit-code ../docs/endpoint-registry.md` (the registry lives at the repo root, as CI checks it).
- Frontend (cwd `runsheet`): `npx tsc --noEmit`, `npm run lint`, `npm test -- --ci`, `npm run test:e2e -- dispatch-board`.

Decisions taken in planning:

- **PL1.** Backend before UI, so the UI is built against real contracts; the UI uses a mocked API layer in Jest/Playwright, never staging, in automated tests.
- **PL2.** The DnD spike (task 1) gates every task that touches `components/dispatch-board/dnd/`. If Pragmatic fails a criterion, the adapter is built on `react-aria-components@1.21.1` instead and the result is recorded in the evidence file; nothing outside `dnd/` changes.
- **PL3.** Prerequisites that change existing behaviour (R25 manifest, explicit dispatch driver, relink primitive, check-in compare-and-set and driver transition guard/gate (task 4b), board-plan guards in MVP surfaces) land first and separately, each with its own tests, because other features depend on them.
